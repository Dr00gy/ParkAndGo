## Overall Findings

- **Create vs. Confirm:** logically consistent; Create produces a `DRAFT`, while Confirm performs the actual reservation check.
- **Availability vs. Confirm:** consistent because all call sites use the same shared `availability.has_overlap()` contract (C05).
- **Cancel vs. State Diagram:** **no contradiction** in the supplied diagram; cancellation from `CONFIRMED` is represented.
- **Intervals:** code and tests implement **`[start, end)`**, but the written specification should state this explicitly.
- **Use-case diagram:** the original diagram was **missing `Prolong Reservation`**; already fixed in `ParkAndGo_consistency_checks_ult.md`.
- **PostgreSQL:** correctly treated as a possible future architecture decision, **not a current requirement**.
- **Precision:** the important numerical values are documented, and the 10× concurrency scenario now has a real measurement behind it (C06 F1).
